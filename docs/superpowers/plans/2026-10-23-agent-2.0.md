> Execute with superpowers:subagent-driven-development or superpowers:executing-plans. The user supplied the feature specification and explicitly authorized continuing through PR 6 without intermediate approval. Never push or open pull requests.

**Goal:** Deliver the remaining five focused branches, stacked on the reviewed avatar engine.

**Tech stack:** Existing Rust/Tauri/React/TypeScript workspace; no new runtime dependencies.

**Spec:** The owner's six-PR Pegoles Agent 2.0 request. PR 1 is `feat/avatar-engine` at `224cb1f`, based on main `21f4af2`.

## Global constraints

- English code, comments, default UI, docs and Conventional Commits; Portuguese UI is available through the requested pt-BR locale.
- Silver/neutral brand. No code or data from unrelated project services.
- No host shell/file/process/URL protocol actions. Exhaustive policy match. No VM network device or webview network/WebRTC.
- Treat guest/model output as bounded hostile data; never render it as HTML.
- New IPC commands require ACL registration, ipcSurface tests and TAURI_IPC documentation. Security changes require THREAT_MODEL and RELEASE_GATES updates.
- Work only inside this repository. Reference source is read-only. Never access live agent configuration or secrets.
- Branch each PR from its predecessor. Never push, open PRs, merge, publish or run cloud inference.
- For every branch: pnpm install from the lockfile without install scripts; bash scripts/check.sh green on pnpm 9.15.9 and Rust 1.97.1; diff/stat/template description saved under target/review/<feature>/.
- Compare touched files with the open Windows draft #12; describe textual and semantic integration risks.

## Review focus

- Preference and history files: bounded reads, validation, atomic replacement and restrictive permissions; disk failures cannot invent success.
- New UI: focus containment/restoration, keyboard operation, disabled controls while saving; no translation or HTML interpretation of guest/model/user content.
- Approval authority: only human-app commands decide; expiry, cancellation, replay and task/computer identity fail closed.
- Takeover: suspend planning/dispatch while the human owns control; finish or cancel only the current bounded input safely, preserve the task for resume, and reject plans produced across a control-generation change. Capture/input bounds and ownership are checked under the same dispatch authority.
- Experimental team mode: explicit opt-in, cloud-only guard, finite step/time budgets, cancellation and final result/event ordering.
